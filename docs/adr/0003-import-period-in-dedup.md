# 导入按账期确认，去重指纹含账期；余额仍为累计账

导入时软件原本不判断文件属于哪个月：文件名只作为备注保存，去重指纹是
`bupan|工单编号` / `refund|客户名|张数|档位`。这带来两个问题：误选上月文件无任何提示；
且 11 月名单里同样的「4张68元」与 10 月指纹完全相同，会被当作重复而跳过，少记账。

**决定（方案 A）**：

1. 导入前弹窗显示从文件名识别出的账期（`yyyy-MM`），由用户确认或修改；取消则不写入任何数据。
   文件名未写月份时，补盘用明细中出现最多的「创建日期」年月，退款用导入时刻，并在弹窗提示核对。
2. 每条导入记录带 `Period` 字段，去重指纹插入账期作为第二段
   （`refund|2026-10|客户|4|68`）。账期相同才判定重复，跨月相同内容可各自入账。
3. 启动时对旧账本自动迁移：按来源文件名／创建日期补出账期，生成新指纹并保留旧指纹
   （兼容回退旧版本）。迁移幂等、只读内存，不改写源文件。
4. 历史「备注」列显示 `[账期] 来源文件名`，便于核对。

**明确不改**：抵扣余额与待补盘仍是跨月累计账，不按月清零、不做月度结算视图（方案 B/C）。
账期只用于防误选与跨月去重，不改变业务口径。

**Considered Options**:
- B 加账期字段并支持按月份筛选查看 —— 留待后续需求明确再做。
- C 按月结算、月初清零 —— 会改变累计账语义，业务规则未确认，否决。

**Consequences**: 依赖文件名含月份才能自动识别；文件名不含月份时依赖数据日期推断，
因此保留人工确认环节作为兜底。同一账期重复导入仍被跳过；不同账期视为不同批次。
