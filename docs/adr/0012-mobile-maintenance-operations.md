# ADR-0012 · 移动端账目维护操作复用共享规则

- 状态：已实施
- 日期：2026-11-18
- 依据：M3 APK 已能搜索客户、查看待补/历史、手工增减与归档；下一步把纠错类操作搬到手机

## 背景

M3 之后，手机上能查看某个客户欠多少张盘、余额多少，也能勾掉已补发或手工增减。但在手机上核对账目时发现：账目转错客户、别名绑错人、重复建档，仍然必须回到电脑处理。

桌面端 `MainForm` 与 `AliasManagerForm` 里已有撤销、转移、别名纠错、合并客户的规则。若把逻辑再复制一份到移动端，两端在「什么记录能撤销」「改名字后旧名字会不会又被绑回来」「合并前要不要留备份」这些细节上会慢慢分叉——而这些恰恰是容易改错账的地方。

## 决策

**新增 `MaintenanceService.cs` 作为账目维护的共享规则层，桌面与移动端同时调用。**

1. `UndoEntry(store, e)` 统一撤销语义：
   - `RefundCredit` / `ManualCredit` / `Deduct`：整条删除。
   - `ManualBupan` 且未补发：整条删除；已补发：只退回「待发」并清 `ProcessedAt`。
   - 工单补盘：只撤销补发标记，源工单记录保留，避免重复导入时被当成新账。
   - 返回给用户看的动作文案，桌面写状态栏、手机写弹窗。
2. `ApplyAliasChanges(...)` 一次性写回主名/别名改动：
   - 主名改名时旧主名自动保留为别名，历史导入仍能命中。
   - 被移除或改旧的别名写入 `ExcludedLinks`，下次导入不会再自动绑回本客户。
   - 转出去的别名加到目标客户，并清掉目标上对应的排除项。
3. `MergeWithBackup(store, source, target)`：合并前先 `Save()` + `Backup(3)` 留下可恢复现场，再 `MergeCustomer()`，最后 `Save()`。合并会移除源客户档案，因此备份是前置条件而非可选项。
4. 桌面端改造：`MainForm.UndoSelected()`、`MainForm.MergeCurrentCustomer()`、`AliasManagerForm.Apply()` 改为调用共享层，界面交互与提示文案不变。
5. 移动端：
   - 客户详情的历史账目加 `CheckBox`，「撤销所选」按共享语义逐条处理；「转移所选」整批调用 `Store.MoveEntries()` 生成 `TransferBatch`。
   - 新增 `TransferLogPage`：列出全部转移批次，选中未撤销批次后整批退回；`Store.UndoTransfer()` 会跳过已删除、已再次转移的条目，避免覆盖后续操作。
   - 新增 `AliasManagerPage`：主名改名、别名新增/改名/删除/转移给其他客户，保存时调用 `ApplyAliasChanges`。
   - 详情页「合并到另一客户」：列出候选目标、展示将转移的账目数、提示合并前自动备份，再调用 `MergeWithBackup` 并返回客户页。
   - 目标客户选择统一用 `DisplayActionSheet`，最多列 8 个，超出时提供名称/别名筛选，避免长列表卡住。

## 后果

- 两端对「撤销什么」「别名怎么排除」「合并是否备份」的口径完全一致，后续只需改 `MaintenanceService` 一处。
- `MaintenanceService.cs` 只依赖 `Model` / `Store`，不含 WinForms 或 MAUI 引用；桌面 net48 用 C# 7.3 也能编译，移动端通过 `csproj` 的 `Compile Link` 共享同一份文件。
- 合并操作不可直接逆转，但合并前的备份可用「我的 → 从备份恢复」或桌面的「恢复备份…」还原。
- 撤销转移只作用于转移批次本身；若这批账目后续又被别的批次转移过，会跳过并在结果里体现为实际撤销条数小于原批次数。
- 别名管理页的改名/删除是「先加排除、再写回」，因此用户误删别名后，需要重新新增同名别名才能恢复自动关联。
