# 客户用归档／隐藏代替删除，新补盘自动恢复显示

补盘完成后客户仍留在列表里，用户希望"清掉"这些客户，但直接删除会连带丢失
抵扣余额与历史账目，且误操作不可恢复。

**决定**：

1. `Customer` 增加 `Archived` / `ArchivedAt` 标记。归档客户默认不出现在列表与搜索中，
   但档案、别名、全部账目原样保留；勾选"显示已归档"可查看并手动恢复。
   旧账本没有这两个字段，反序列化时 `Archived` 默认 false，无需迁移。
2. 归档前若还有未补盘张数或未用完的抵扣余额，弹出警告并二次确认。
3. **自动恢复**：归档客户下月又有补盘时自动重新出现。导入链路的客户匹配
   （主名／别名）本来就查全部客户（含归档），因此只要命中并真正入账了
   `BupanOrder` / `ManualBupan` 条目，就解除归档并在状态栏提示。
   重复导入被去重跳过时不触发；仅退款／抵扣入账也不触发。

**边界**：新名字与归档客户完全对不上、且用户在"关联/新建"弹窗里选了"新建"时，
会创建新档案，归档的那个仍保持归档——这是既有客户归属逻辑，需人工在"显示已归档"里
合并或恢复。别名机制可大幅降低这种情况。

**Considered Options**:
- 彻底删除客户及其账目 —— 否决：余额和历史丢失，不可撤销。
- 只删档案保留账目 —— 否决：产生无法归属的孤儿记录。

**Consequences**: 客户主库会持续累积归档档案，列表默认过滤后仍保持清爽；
归档状态会被备份一起带走（ADR-0003 的备份机制覆盖此字段）。
