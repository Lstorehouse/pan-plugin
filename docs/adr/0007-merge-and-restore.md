# 别名可改名、客户可合并、备份可恢复

实测发现两类问题：

1. 导入时若把昵称（如"黄强"）**新建成了独立客户**，它会在列表里单独占一行。
   用户以为它是别名，但「管理别名…」只处理当前客户的别名文本，改不到另一个客户档案。
   同时别名本身也缺少直接改字的能力（只能删除后重建）。
2. 只有备份、没有恢复入口。合并客户这类不可逆操作缺少兜底手段。

**决定**：

- 别名管理增加「改名为 + 应用改名」，可就地修改别名文本；旧名字自动记入
  `ExcludedLinks`，避免下次导入又被模糊候选绑回。所有改动仍暂存到「确定」才生效。
- 新增 **合并到另一客户…**：源客户名与全部别名并入目标客户、账目逐条转移
  （复用 `TransferBatch` 日志）、移除源客户档案、清理源客户的排除关联。
  执行前自动 `_store.Backup(3)` 留现场，并二次确认。
- 新增 **恢复备份…**：`Store.ListBackups()` 汇总程序目录与回退目录的 `store-*.json`；
  `RestoreBackupForm` 显示时间/大小/客户数/账目数预览，二次确认后恢复。
  `RestoreFrom()` 先校验 JSON，再把当前账本另存为 `before-restore-*.json`
  （刻意不匹配 `store-*.json`，不会被 3 份轮转删除，自身也只留 3 份），
  最后原子替换 `store.json` 并整体重载账本。
- 恢复逻辑抽成可注入路径的 `RestoreFromTo(backup, targetFile, backupDir)`，
  便于在临时目录里做验证而不触碰真实账本。
- 顶部一排按钮放不下，把「显示已归档」勾选项移到左栏客户列表上方
  （用 TableLayoutPanel 固定行高）。

**Consequences**: 合并客户不可逆，恢复备份是唯一回滚手段，因此合并前强制自动生成备份。
`before-restore-*` 文件与 `store-*` 备份分开计数，用户可在资源管理器里区分。
