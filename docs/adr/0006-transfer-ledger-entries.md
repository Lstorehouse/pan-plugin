# 账目可逐条转移，按批次记录日志并可整批撤销

别名纠错（ADR-0005）只解决"以后归到谁"。若错误关联已经把补盘工单／抵扣记录
写入了错误客户的 `CustomerId`，需要把历史账目搬回正确客户。

**决定（方案 A）**：

1. 客户详情的历史列表带勾选框，勾选后点「所选记录转移到…」→ 搜索并选择目标客户
   → 二次确认。`Store.MoveEntries()` 逐条改写 `CustomerId`，跳过已删除或不在源
   客户名下的条目。待补盘与抵扣余额随客户归属自然变化。
2. 每次转移生成一条 `TransferBatch`（时间、源/目标客户、条目 Id 列表、条数），
   「转移记录…」可查看并整批撤销。撤销把条目退回源客户，标记为 Undone。
3. 撤销安全性：已删除、已不在目标客户名下、或被**更晚的转移批次**重新处理过的
   条目自动跳过，避免覆盖后续操作；提示实际撤销与跳过条数。
4. 顺带修正：两个 ListView 原先 `CheckBoxes = false`，导致既有的
   「勾选项标记已补发」根本无法勾选、已补发状态也不可见。现均开启；
   MarkDone 只处理本次新勾选的未补发条目，避免把旧勾选重复计数。

**不做**：合并客户（把两个档案及账目合为一个）。逐条转移 + 撤销已能纠错，
合并是不可逆的批量操作，待确有需求再做。

**Consequences**: `TransferBatches` 随账本一起持久化与备份；旧账本无该字段，
`Store.Load` 初始化为空列表。转移只改客户归属，不动 `Ref` 去重指纹，
因此不会让同一工单在下次导入时被重复计入。
