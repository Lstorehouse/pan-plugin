# 别名可管理，已解除的关联不再被重新推荐

别名原先只增不减：导入时 `AddAlias()`、以及「关联/新建」弹窗里选了已有客户之后写入，
界面没有查看/删除/改名入口。由于 `Customer.Matches()` 是精确匹配，一旦名字被误绑到
A，后续导入同名数据会静默归到 A，连确认弹窗都不再出现，错误持续累积。

**决定**：

1. 新增「管理别名…」对话框：改主名（旧名自动保留为别名）、删除别名、新增别名、
   把误绑的别名转移给另一客户。改动先在对话框暂存，确定才落盘，取消不留痕迹。
2. `Store.ExcludedLinks` 记录被用户解除的「名字 ↔ 客户」组合。导入时若该名字没有
   精确命中，模糊候选会过滤掉这些客户，避免再次被推荐绑回错误客户。
   转移到目标客户时会清除目标上的排除记录。
3. 旧账本没有 `ExcludedLinks` 字段，`Store.Load` 初始化为空集合，无需迁移。

**明确不做**：不搬动已经入账的补盘／抵扣记录。错绑若已产生账目，其 `CustomerId`
已经固定，需要单独的「转移账目／合并客户」功能来处理，避免在没有二次确认的情况下
改动历史数据。

**Consequences**: 解除关联后，下次导入同名数据会重新弹出「关联/新建」对话框，
用户有机会选对归属；`ExcludedLinks` 会随账本一起被备份。
